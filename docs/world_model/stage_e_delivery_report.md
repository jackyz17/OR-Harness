## 1. Files and core functions

New:

- `src/or_harness/world_model/history_retrieval.py`
  - `build_history_retrieval` (multi-view embedding recall → merged,
    thresholded, task-diversified pool with execution/closed-evaluation
    facts and the GLOBAL G/C/R blocks);
  - `build_query_views` (problem text / each candidate method / conditions);
  - `select_g_history_evidence`, `select_c_history_evidence`,

  - `global_g_statistics`, `global_c_statistics`, `global_r_statistics`;

  - coverage refreshers and the config/threshold helpers.

- `docs/world_model/stage_e_unified_history.md` (design/config/limits).
- `docs/world_model/history_threshold_calibration.md` (threshold evidence;
  generated by the calibration sub-task).

  execution item (same index file; legacy indexes still load);
  `rebuild`/`upsert` accept `aux_documents`.
- `strategy/index_sync.py`: writes the task-text auxiliary vector and includes
  it in an explicit rebuild.
- `strategy/evidence_views.py`: provider compact pair keeps cost
  `scope`/`window_coverage`/actual solving conditions/reusable-artifact fact

  `DEFAULT_GCR_EVIDENCE_CHARS` 16000 → 24000.

  `history_retrieval` metadata + the three unified blocks, and no longer
  imports the retired keyword/group selectors.
- `world_model/cost_signal.py`: `cost_conditions` has no phase; the old
  strict/broader group selection and `conditional_cost` group matching were
  deleted; `decision_cost_scales` delegates to the global distribution;
  `conditional_cost_statistics` no longer groups by phase (stored audit stays
  readable).
- `world_model/g_signal.py`: `select_candidate_method_evidence` and its
  keyword-term helpers were deleted (the `shared_method_terms`
  false-positive mechanism).
- `world_model/r_signal.py`: condition-group `select_r_evidence` and its

- `world_model/request_budget.py`: unified case caps, new coverage refreshers,

- `api.py`: one retrieval per decision (bounded to the root snapshot moment),
  frozen into the context; a historical reconstruction reports
  `not_reconstructed` instead of reading today's index; single-candidate
  predictions now build the context WITH the candidate so the method view

- Tests updated: `test_c_signal_review.py`, `test_r13_remaining_cost.py`,
  `test_r_technical.py`; `test_stage_d_prediction_evidence.py` replaced by

## 3. Before/after provider material (same fixture, same history point)

Controlled fixture: two closed episodes (tool_calls 8 and 20), then a third
decision for the same task.

| signal | before (81f8bec) | after (this work) |
|---|---|---|
| G | `wm-g-method-evidence/1`, 2 cases, first case `comparison_role=strict_condition_match`, `method_match=shared_method_terms` with generic terms `[acceptance, available, chain, change, coupling, factory]`, no global block | `wm-g-history/1`, 2 cases, `relevance=same_task`, NO shared-keyword field, each case has the observed label + `global_history` (n/MAE/Brier/AUC/bias/bins) |
| C | provider block has `current_conditions.phase=existing_model`, 1 strict range + 2 cases; no global distribution | `wm-c-history/1`, `phase_used=false`, 2 strict cases with the same four-dimensional actuals, no phase, `global_cost` with n/p50/p90/error direction for all four dimensions |
| R | 1 solver-interface condition group, 0 local cases, global base rates only | `wm-r-history/1`, 2 local cases with all three event labels, `global_event_base_rates` + `global_prediction_performance` |
| history record | none | `history_retrieval`: backend, per-view floors, query names, pool/admission counts, degradation |

Provider block sizes on that fixture (chars):
before G 1455 / C 5668 / R 3680 (total 10803);
after G 2531 / C 3042 / R 3665 (total 9238) plus `history_retrieval` 1149.
The after-C block is SMALLER despite carrying a global distribution, because
the phase/condition-group scaffolding is gone.

A bigger-history fixture (two closed C episodes in `c_fixtures`) shows the
same retrieval point producing **2 strict local cost cases** after vs 1 strict
range + 2 cases before; and the first G case changes from a generic
`shared_method_terms` match to an explicit `same_task` relevance with no
keyword claim.

## 5. Remaining limits

- Threshold calibration is small-sample and backend-specific; a lexical
  backend only matches text overlap, so a reworded cross-task analogy is
  honestly missed. Re-derive the floors for any real embedding model.
- The retrieval pool is frozen into the prediction context (bounded to 30
  rows). It is not a new database, but it makes stored contexts larger than
  the old summary.
- An index built before this stage has no task-text vectors; the problem view
  falls back to the full document (recorded as `legacy_full_document`) and
  same-task similarity is diluted by the method suffix. Run
  `orx rebuild-index --layer execution`.
- Executions from a still-open episode can appear as R `execution_only` cases
  (a real fact visible before the decision) but never enter the global
  calibration denominators, which stay closed-window only.
- A dimension with no complete ledger observation stays incomplete; no
  estimate is substituted. `tool_calls` recovery depends on the existing
  complete-ledger logic; contradictory aggregate meters keep it unknown.
- Cost scales for U now use the global pre-decision p90 per dimension. The U
  formula, weights and early/late coefficients are unchanged; the source
  population changed from condition groups to the global distribution, which
  is the intended removal of the phase/groups dependency.
